## A mismatch I found and fixed

With the environment stripped, the child no longer inherited `OPENPYXL_LXML=False`, so on a machine with lxml installed it parsed with lxml (light) while the server, with the variable set, parsed with the standard library (heavy). In the measurement, six bomb files then passed the child at 417 MiB and took the server 865 to 1,079 MiB. The image has no lxml, so it does not happen there, but the check is only worth anything if the child parses as the server does. The parent now sets the child's `OPENPYXL_LXML` from what its own openpyxl is using (`_xml_reader_mode`, derived, not copied from the environment). A test fixes it for both modes. After the fix all of the reviewer's files behave as in the measurement.
