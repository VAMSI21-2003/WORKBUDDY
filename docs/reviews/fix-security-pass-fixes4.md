## What changed

`skills/excel/workbook.py`:

- `check_workbook_limits` keeps the cheap instant checks in the server (part count, declared unzipped size, DOCTYPE/ENTITY in any part, `[Content_Types].xml` over 16 MiB as on `main`), then calls `_scan_in_child`.
- `_scan_in_child` starts `python -I -c …` with `RLIMIT_AS` 512 MiB (`SCAN_MEMORY_BYTES`) and a 60 s timeout (`SCAN_SECONDS`), one BLAS thread (each reserves address space the cap would count), and the repository root on its path. The child writes `1000` to its own `/proc/self/oom_score_adj` first.
- The child (`_scan_in_this_process`) counts what the table's reader would build (`_reader_verdict`: rows over all sheets together, columns, cells, characters in a cell, bytes of text), then reads the file the way the app does (below).
- The per-part cap lists are gone: `workbook.xml` 1 MiB, `styles.xml` 8 MiB, the shared-strings count, the `TOO_BIG_PART` and `TOO_MANY_STRINGS` sentences, `_part_verdict`. The `[Content_Types].xml` size check stays, because `main` refused that part by size before openpyxl saw it and P3 was a regression against `main`; the child would also refuse it, but not instantly.
- The text cap counts what CPython stores (R4-3): 1, 2 or 4 bytes a character by the widest character in the cell, `MAX_TEXT_BYTES = 4_000_000` (the reviewer's figure: a turn at it took 564 MiB for ASCII and 475 MiB for emoji, measured by the reviewer). Not re-measured as a whole turn here.

## The owner's conditions

1. **The child runs the same reader the app uses, not a lighter streaming read.** The reviewer's prototype ran only the row-by-row walk, so it did not hold a table in memory. `_read_as_the_skills_do` now also calls `sheet_names` (the planner's and Inspector's listing) and holds a default `pd.read_excel` and a `dtype=object` read at once, which is what `SpreadsheetAnalysisSkill` does and is the largest read the app makes. It is the same function calls, not a copy, and `check_workbook_limits` returns at once inside the child so those calls don't start another child. Left out, on purpose: the layout check and the formula count stream cells one row at a time over the same load, so they add time (12 s on a million cells) and not memory. The analysis's own memory after the read (ydata-profiling, Splink) is not in the child; it is bounded by the cell cap and by the 100-character and pair limits in `skills/excel/analyze.py`. A file the child passes needs about what the child used for the reads; a turn on top of that needs more, which is why the figures must be measured in the image (below).
2. **One check at a time; child sets its OOM score; fit in 1 GiB.** A `threading.Semaphore(1)` holds the whole check; a second check waits `SCAN_WAIT_SECONDS` (10) and then the turn refuses with `CHECK_BUSY` ("the server is busy checking another workbook, so I couldn't check this one; please try again in a moment"), which the reply gives as "I can't work on this file: …". The API never parses an upload (`backend/uploads.py`), so the check runs inside a turn and the busy answer is the turn's reply, not an HTTP 429; the wording follows `ErrorCode.SERVER_BUSY`'s. A busy answer is never kept as a verdict on the file, and a thread that waited uses the verdict of the check that ran meanwhile for the same file. The child sets `oom_score_adj` to 1000. Whether server plus one child fits in 1 GiB is **not known**: here the child of a refused bomb reaches 410 to 415 MiB resident (under the 512 MiB address-space cap) and a process that has imported the skills is 79 MiB, so the child alone is about 335 MiB over a bare import. `scripts/measure_workbook_check.py` (new) builds the reviewer's bomb files and an ordinary at-cap file and, per file, runs the check in a fresh process and prints the seconds, the child's peak memory, the server-side peak after also reading the file, and the container's memory limit and kernel OOM kills. The owner runs it in the production image on the VM: the command is in the script's docstring (`docker run --rm --memory 1g --memory-swap 1g -v "$PWD/scripts:/app/scripts:ro" --entrypoint python workbuddy scripts/measure_workbook_check.py`). **The limits (512 MiB, 60 s) are unmeasured until then, and the PR says so.** On this sandbox 1,000,000 numeric cells took 39 s, against 60 s.
3. **A memory error, timeout or crash refuses the file.** `MemoryError` is re-raised out of every catch-all that would read it as "can't be read" (`_reader_verdict`, `sheet_names`, `_sheet_problem`, `formula_cell_counts`), and the child answers `TOO_COSTLY`. A timeout answers `TOO_COSTLY`. A non-zero exit (a kill, a crash, an abort), no answer, an unknown answer, or a child that could not be started answers `CHECK_STOPPED` ("the check of the workbook was stopped before it finished, so I can't tell that it is safe to open and I won't open it"). The child answers with a number that the parent maps to a fixed sentence, so nothing the file or the child says reaches a reply. A crash is kept as the file's verdict for the process's life; a child that could not be started is not. Tests for each (`tests/skills/excel/test_scan_child.py`), with 7 stand-in children, and mutations: re-raise removed from `sheet_names`, status check removed, unknown answers passed, the tables not built, the limits not handed over, the semaphore widened, the timeout passed and the memory error passed all fail a test.
4. **Cheap pre-checks kept; per-part lists removed; `[Content_Types].xml` does not regress.** See above. A 55 MiB `[Content_Types].xml` (P3) is refused in 0.0 s with main's sentence, without starting a child (test).
5. **The tests that changed limits in the test process.** The parent now passes its current `MAX_ROWS`, `MAX_COLUMNS`, `MAX_CELLS`, `MAX_CELL_CHARS` and `MAX_TEXT_BYTES` to the child as JSON on its command line (not the environment), and reads `SCAN_MEMORY_BYTES` and `SCAN_SECONDS` when it starts it. So a test that monkeypatches a limit in the test process tests the child's check against that number (`test_the_parents_limits_are_the_ones_the_child_checks_against` proves it; mutating it away fails it and the three monkeypatching tests in `test_hostile_workbooks.py`). The tests for the removed caps were deleted, the text-cap test now counts bytes (ASCII, CJK, emoji) and the limits test names the new numbers. Tests that need hostile parts cost what they cost in the image set `OPENPYXL_LXML=False`, because the image has no lxml and lxml parses much more cheaply.
6. **R4-4.** The sentence is now "Some of your wording overlaps what I did. If you asked for anything beyond that, I haven't done it, so check the copy is what you wanted." It is true for "…and delete the file", for a paraphrase the mention pattern didn't match, and for a double-listing.
