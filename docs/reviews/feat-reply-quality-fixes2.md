## M1: replaced, not patched again (`docs/process/review-loop.md`, "Stop patching a mechanism that keeps failing")

Round 1 and round 2 both found the same false "can't do" about a delivered report, in the same function (`buddy/outcome.py` `_no_skill_outcome`). Round 1's fix widened the word lists that say "this phrase is only a report request"; round 2 showed that no such list can be finished (17 of 40 fresh, ordinary wordings still contradicted themselves: "Can you provide a report?", "analyze the first sheet", "report on everything"). So I removed the thing that kept failing, the list of words a report phrase **may** contain, as the test for "nothing else is asked".

**New rule (one place, `_no_skill_outcome`):** when the reply states the report itself, an `unsupported` phrase that contains a report request produces no "can't do" sentence, **unless it also names work Buddy can't do**, judged by a *closed* list of verbs of such work (`_OTHER_REQUEST_WORDS`: sort, filter, chart, graph, plot, highlight, colour, merge, split, rename, translate, convert, email, print, upload, share, export, pivot, delete, drop, insert, replace, fix, correct, remove, add, clean, save, download, post, publish, "send it/them/this/that/to", ...). The list holds verbs of other work. It deliberately has no word a report is described with, and none of the quantity words (count, sum, total, average, group, round) or "format"/"open"/"copy"/"move" that appear in ordinary report descriptions. The old rule is gone for report phrases: a phrase that mentions a report and none of these verbs is the report and nothing else; a phrase with one of them keeps the existing "I can't do this part yet" sentence and "Partly done".
- **The failure moves to a safe place, and it is stated here:** a report phrase with an extra that has no listed verb ("... and put it in a pdf") is not mentioned at all, so the lead word can be "Done" with that extra left undone. The reply stays true; it doesn't name the extra. Before, the unlisted word kept the sentence and the sentence was false for ordinary report phrases. A false "can't do" about a delivered report is the failure the owner asked to end (item 3), so I chose the failure that stays true. **For the owner:** if you want the other direction, say so; the alternative that cannot fail either way is a Brain `analyze` action in its closed vocabulary (the model says which phrase is the report), which is a change to the ledger's action table.
- The connector criterion the reviewer's prototype used ("and/then/also" keeps the sentence) is **not** used: "report on missing values and duplicates" has a connector and no extra.

**Tests (`tests/buddy/test_reply_quality.py`):** the 40 fresh wordings of the round-2 reviewer, plus 405 generated wordings (9 request verbs × 5 report nouns × 9 objects), each asserted to leave no "can't do" action; 9 wordings that name other work ("... and make a chart", "... and email it to Bob", "... then delete column B", "... and send it to my boss", "... and add a total column") that must still say "can't do"; 5 ordinary wordings through `build_engine` in all three speakers, alone and after a dedupe, with no "can't do", no "Partly done" and no "Your message mentions … didn't run". With the new `if` disabled, 358 of the tests fail; with "sort" removed from the list, the sort case fails.
