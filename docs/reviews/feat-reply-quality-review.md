## M1 (MEDIUM, [Certain] mechanism, [Likely] reachable): a report is delivered and the same reply says it can't be done

- **Where:** `buddy/outcome.py` `_no_skill_outcome` (the `if report_stated:` block, line 484, with `_FILLER_WORDS`, line 411) against `buddy/actions.py` `is_only_a_report_request` (line 237, with `_REPORT_FILLER`, line 210). The planner decides "this phrase is only a report request" with the wider word list; the outcome renderer decides it with the narrow one, whose own rule says never to add "file", "data", "it", "this", "my", "of".
- **Scenario:** Brain, whose prompt names "a report" as the example of `unsupported`, returns `{"action": "unsupported", "source_phrase": "analyze my file"}`. 19 of 34 plausible wordings do the same: "analyze my file / the file / it / my data / this spreadsheet", "summarize my data / the file / this / it for me", "give me a summary of the file / of my data", "give me a report of the file", "give me an analysis of the file", "write me a report about this spreadsheet", "generate a report of all the issues", "report on the duplicates", "show me a summary of the problems", "a short summary would be great". "give me a report", "send me a report", "I need a report" and "give me a report on this file" are handled.
- **Reply, nothing changed (all three speakers):** "I read your request as something I can't do yet. I can remove duplicate rows, remove empty rows, and look a spreadsheet over for possible problems. Report on your original file: 2 rows repeat an earlier row exactly; name: 1 missing value (16.7%); amount: 1 missing value (16.7%). No changes were made to any file this turn." The base gave the findings with no "can't do" sentence, so this part is a regression.
- **Reply, after "remove the duplicate rows and analyze my file":** "Partly done — removed 2 duplicate rows. I read part of your request as something I can't do yet. The copy has 4 rows, ... Report on the copy: name: 1 missing value (25.0%); ..." The report was delivered and the lead word says it was not (a false "can't do", and "Done" became "Partly done"). The base had the same false "can't do" (with the findings as "I also noticed:"); item 3 of the design is meant to end exactly this.
- **Reach:** the mechanism is certain. Whether the real Brain copies "analyze my file" whole or only "analyze" (which is dropped correctly) is a model behaviour I could not check.
- **Fix:** one predicate for both stages. At the top of `_no_skill_outcome`: `if report_stated and is_only_a_report_request(entry.source_phrase): return None`. Widen `_REPORT_REQUEST` so the report's object is part of the request (`of|on|about|for` + determiners + `file|sheet|spreadsheet|workbook|data|table|issues|problems|duplicates|rows|columns|errors`) and add "would be great / thanks" to `_REPORT_FILLER`. A phrase with any other content word ("sort by summary") stays a "can't do". Prototype in a scratch copy, `out/prototype-fix-for-M1.diff`: 18 of the 19 wordings become "Done — ... Report on the copy: ..." (left: "a short summary would be great"), and the 516 tests in reply-quality, outcome, actions, planner and voice still pass. Add a test over the wordings in `probe_b_report_phrases.py`, alone and after a dedupe.

## H1 (HIGH, [Certain] mechanism, [Likely] reach): "Done" when part of the request was not done

- **Where:** `buddy/outcome.py` `_no_skill_outcome` lines 504-512 (`if not _OTHER_REQUEST_WORDS.search(lowered): return None`) with `_OTHER_REQUEST_WORDS` (line 445). Brain's `unsupported` entry for the extra is dropped; `OutcomeReport.lead_word` then sees only `DONE` actions and says "Done".
- **Scenario:** Brain lists the dedupe and an `unsupported` entry whose phrase holds a report noun or verb and a verb the list lacks. Messages: "remove the duplicate rows and put the report in a new sheet / write the report to a new tab / send the report to my boss / give me a report in pdf / give me a report in French", and, not even a report request, "... and update the summary / rewrite the summary / finalize the report / improve the analysis" (the bare noun reads as a report request, backlog RQ-L2).
- **Reply (template wording; friend and focus add their opener and file line, same lead word):** "Done — removed 2 duplicate rows. The copy has 4 rows, with 0 duplicate rows remaining. Saved as `report_deduplicated_session-1-task-1.xlsx`. The copy has the values only; ... Report on the copy: name: 1 missing value (25.0%); amount: 1 missing value (25.0%)." My read of the delivered copy: one sheet, 4 rows; nothing sent, no new tab, no summary changed. Base, same input: "Partly done — removed 2 duplicate row(s). I can't do this part yet: “write the report to a new tab”." With nothing else asked, the reply is the report and "No changes were made to any file this turn.", which is true.
- **Why HIGH:** "Done" is the lead word the outcome design reserves for a request that is complete (`request_complete`; backlog item 1: "no bare 'Done' for a compound request with an item that wasn't done"). The writer and the round-2 reviewer recorded this as a cost of the closed list and "the reply stays true"; by the severity definition ("a reply claims something that didn't happen") it is the claim. The owner may decide otherwise (see "For the owner").
- **Fix (replace the mechanism, `docs/process/review-loop.md`: two rounds in a row in this function):** delete `_OTHER_REQUEST_WORDS` and the early return. Keep `is_only_a_report_request(phrase)` (first line of `_no_skill_outcome`) as the only way to stay silent. For any other phrase that holds a report request (`had_report`) and has a word outside `_FILLER_WORDS` left over, return a new `NOT_DONE` outcome with reason `REPORT_ONLY` and no `source` (so `lead_word` is neither "Done" nor "Partly done"), rendered as one fixed sentence that is true however the leftover is read, e.g. "The report is all I did for that part of your request." Prototype: `out/r3-prototype-fix-for-F1-F2-F3.diff` (`buddy/outcome.py` part). With it: `r3_extras` 50 of 50 say it (0 silent); `r3_nonreport` no "Done"; `r3_listed` 84 of 88 turns clean; `r3_columns` 102 of 102 clean. **Cost, measured:** 32 of 80 turns of round 2's 40 pure wordings (the ones with a descriptor such as "missing values", "first sheet", "everything") now carry that sentence and no "Done" (flatter, never false); in `probe_a` 15 of 489 replies change (5 per speaker): "what's the analysis?" and "give me a full report of everything wrong" gain the sentence, and "remove the duplicate rows and sort by summary" loses its explicit "can't do" (it is replaced by the same neutral sentence, which is true but less informative); 367 of the 677 tests in `tests/buddy/test_reply_quality.py` assert the old behaviour (silence for descriptors, `no_skill` for the 9 extras) and need new expectations. The no-cost alternative is a closed `analyze` action in Brain's vocabulary so the model, not a word list, says which phrase is the report (owner's decision). Tests to add: the lists in `r3_listed.py`, `r3_columns.py`, `r3_extras.py` and `r3_nonreport.py`, through `build_engine`, asserting no "Done" / "Partly done" and no "can't do" beside "Report on".

## M2 (MEDIUM, new, caused by this round's N2 fix; [Certain] mechanism, [Likely] reach): genuine report requests are vetoed

- **Where:** `buddy/actions.py` `_REPORT_BY_THE_PERSON` (`\bmyself\b` anywhere in the message; "I can/I'll/I will/I'm going to" + up to 3 words + check/look/review/inspect/analyze/summarize) and the verb alternative of `_REPORT_NEGATED` ("don't/won't/never/no need to" + up to 2 words + a verb), applied to every alternative of `_REPORT_REQUEST` through `mentions_report`.
- **Scenario:** "give me a summary so I can review it", "give me a report so I can check it", "analyze my file so I can look at the problems", "I built this file myself, can you analyze it", "I'm new to this myself, give me a summary of the file", "I will review it later, give me a summary now", "don't hesitate to give me a report on everything you find". 14 of 30 such messages are vetoed (`out/r3-guards-head.txt`).
- **Reply:** with Brain's `unsupported` phrase: "I can't do that yet: “give me a summary”. I can remove duplicate rows, ... Here's what I noticed when I looked it over: 2 rows repeat an earlier row exactly; ... Want me to tackle any of these? No changes were made to any file this turn." With `unclear`: "I didn't read that as something I can do. ..." plus the same findings. With `conversation`: "Hello. I can remove duplicate rows, remove empty rows, ... Tell me what to do with your file." Round 2's source gave "Report on your original file: ..." for all three (`out/r3-guards-engine-*.txt`). The "can't do" is false next to a summary of the problems; the greeting ignores the request.
- **Fix:** apply `_REPORT_BY_THE_PERSON` and the verb negation only when the request was made by the "check / look at / review / inspect the file" or "what's wrong with" alternatives, never when a report noun or verb is present ("report", "summary", "analysis", "overview", "rundown", "analyze", "summarize"); scope `myself` to the clause of the verb (`[^.;,!?]{0,40}`) and require an object (file, sheet, data ...) after "I can/I'll ...". Prototype in the same diff (`buddy/actions.py` part): 4 of 30 genuine requests vetoed (three are round-1 noun negations: "don't forget to", "don't hesitate to"), 0 of 14 declines missed; the 388 tests in units, actions, planner, outcome and voice pass.
